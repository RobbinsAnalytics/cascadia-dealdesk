# Cascadia Deal Desk — what an agent needs to know

Pricing governance and margin leakage analytics on **synthetic** data. It
publishes `docs/` as a static site to GitHub Pages, and it publishes nothing
else.

## The data is invented, and regenerating it is a deliberate act

**There is no real pricing data in this repository and there never will be.**
Every customer, part number, price, and person was invented by `src/generate.py`
from **seed `20260801`**, as-of **2026-08-01**, over the window
**2024-08-01 → 2026-07-31**. `governance/generator_assumptions.md` records those
parameters and is itself auto-generated by that script.

**Do not run `src/generate.py`, `src/build_db.py`, `src/conform.py` or
`src/build_pages.py` in passing.** Regenerating the dataset or the pages is a
deliberate act, taken because someone asked for it — never as a side effect of a
task about something else. Those four are in the `ask` block of
`.claude/settings.json` for that reason, and **that block does not bind under
`bypassPermissions`** (`SESSION-RULES.md` rule 3). Under the estate's default
mode it does; under bypass this sentence is the only control, which is why it is
written here rather than left to the config.

`generate.py` is deterministic — the same seed produces byte-identical CSVs, and
`src/validate.py` proves it by regenerating into a temporary folder and diffing.
**That determinism is this module's reproducibility guarantee.**

## There is no freeze here, and that is not an omission

**This module has no `governance/freeze.toml` and no `src/validate_freeze.py`,
and it must not acquire either.** `PRINCIPLES.md`'s scope clause binds its rules
to *live-data modules — anything built from a real external source on a
reproducible pipeline*. Deal Desk has no external source, no retrieval date, and
no snapshot to freeze: **the seed is the guarantee, not a freeze.**

The estate's `check_module_readiness.py` already treats this repo as **N/A** on
the freeze arm, correctly, and prints it as *"not applicable, which is not the
same as passing."* **A sibling module's handoff instantiates a freeze; copying
that here would be wrong.** Stated rather than left absent, because an agent that
finds no freeze in a data module will otherwise assume one is owed.

**Note the word "freeze" appears in `.gitattributes` meaning something else** —
the committed CSV snapshot under `data/raw/`, which stays byte-identical because
line endings are declared LF. That is not a PRINCIPLES freeze.

## Committing

**Stage by name — never the two blanket forms.** They are denied in
`.claude/settings.json`, and that block does **not** bind under
`bypassPermissions`. What binds is
`.claude/hooks/no_blanket_add_or_force_push.py`, a `PreToolUse` hook.

**`.gitattributes` prevents line-ending churn; the git `pre-commit` hook in
`.githooks/` catches what gets through and refuses the commit, and it fails
closed.** It is inert until `git config core.hooksPath .githooks` has been run
**in this clone** — the scripts travel with a clone, the config line does not.
Run `python .claude/hooks/hook_test_matrix.py` to confirm all three guards
behave as declared; it uses a throwaway repo and takes about a second.

**On a Linux or macOS clone, `.githooks/pre-commit` must be executable or git
skips it silently.** It is tracked here as mode `100755` for that reason. A
non-executable copy does not error, does not warn, and passes every check that
inspects file *contents* — the only thing that catches it is the test matrix's
end-to-end case, which stages and commits for real. If that case fails and the
other 49 pass, check the mode before you check the script.

**A stale `.git/index.lock` left behind when a git process dies** is this repo's
recurring git failure — it is one of the three things `publish-dealdesk.ps1`
exists to handle. **The fix is to delete the lock file and retry**; nothing is
corrupted and no recovery is needed beyond that.

**`publish-dealdesk.ps1` is untracked, and whether it should be is undecided.**
Do not add it, do not delete it, and do not let it into a commit by accident —
which is another reason to stage by name.

## Publishing

**GitHub Pages serves this repo, from `main`.** The GitHub API reports
`has_pages: true`, and `main` is the repository's default branch and its **only**
branch — there is no `gh-pages`. `docs/` holds the site (`index.html`,
`customer.html`, `assets/`, `data/`) and the repo root holds no `index.html`, so
`/docs` on `main` is the source. *Verification strength, per `SESSION-RULES.md`
trap 6.4: this is repository **state** read from the API plus the file layout —
the live URL was not fetched, and the Pages source directory setting was not read
directly.*

**So a push to `main` publishes.** Work on a branch and let `main` stay
publishable.

**Never hand-edit anything under `docs/`.** It is generated by
`src/build_pages.py`, which inlines the JSON at build time so the published page
makes no runtime network call and works from `file://`. `docs/data/dealdesk.json`
is the data contract and is generated too. Hand-editing a generated file is a
recurring failure across this estate.

## The charts have declared failures, and they are not yours to fix

**Do not fix, retouch or re-render any chart** unless that is explicitly the
task. This module carries a **live, declared Rule 2.3.7 non-conformance** — a
palette hue used as text below 4.5:1 — declared **RETROACTIVE against this
module by name** in `cascadia-standards/design-system/VIZ-PRINCIPLES.md`, and
disclosed in the palette's known-weakness box **until corrected**.
`governance/chart-review.md` separately records a `2.3.3 FAIL (INVARIANT)`, a
justified `2.4 FAIL(3)`, and a `2.7 FAIL(4)` on chart 7.

**The unevenness across modules is deliberate signal.** Correcting any of it
here in passing would erase the evidence for a disclosure that is currently
doing its job.

## Content

**Canonical domain is `https://www.robbinsanalytics.com`.** Every absolute URL
uses it.

**Two files under `governance/` are generated, not authored:**
`generator_assumptions.md` (by `src/generate.py`) and `validation_report.md` (by
`src/validate.py`). The reading-panel and chart-review documents beside them are
authored records and are not regenerated by anything.
